# 09 線上看到其他玩家移動「頓一下頓一下」（11/07，遊戲企劃 game；使用者回報）

## 1. 原因（看 js/net.js）
- 自己的位置**每 0.25 秒才送一次**（`netTick`：`netSendT = 0.25`），網路還會有快有慢。
- 收到後畫別人的方式（`netTick` 裡）：每幀往「最新收到的位置」靠近 `dt×10`，大約 0.2 秒就到了，**到了就停住，等下一包**。下一包常常 0.25–0.4 秒才到 → 走、停、走、停 = 頓頓的。
- 走路動畫也一樣：`o.walk = dd > 1 ? … : 0`，一追到目標腳就停，看起來更卡。
- 放招時 `netCast` 會讓下一包提早到 0.06 秒，封包間隔更不平均，追的速度忽快忽慢。

## 2. 修法（不用加流量）
1. **插值緩衝（延遲 0.3 秒播放）**：每收到一包記 `{x, y, 收到的本機時間}` 存進 `o.buf`（留最近 6 筆）。畫的時候用「現在 − 0.3 秒」這個時間點，在前後兩筆之間**等速內插**。這樣永遠有下一筆可以走過去，不會停。別人的畫面晚 0.3 秒，看不出來（只是看別人，不是打架）。
2. **緩衝用完時往前預測**：網路卡、0.3 秒內沒有新包時，用最後兩筆算出速度，最多往前推 0.25 秒，然後慢慢停。
3. **送速度**：presence 多送 `vx, vy`（取整數），預測更準；停下來的那一刻一定送一包（速度 0），別人才不會滑過頭。
4. **走路動畫看速度**：用內插出來的速度決定腳有沒有在動，不看「離目標多遠」。
5. 傳送（一次跳超過 200）照舊直接瞬移，並清空緩衝。
6. 不改送出頻率（0.25 秒）：RTDB 下載量是「人數 × 人數」在漲，提高頻率會很快吃掉免費額度；插值做好，0.25 秒就夠順。

## 3. 驗收
- 兩個瀏覽器分頁登入兩個測試帳號，一個繞圈走，另一個看：要連續、等速，不能走走停停。
- Chrome 開發者工具把網路調成「慢速 4G」再看一次：可以稍微落後，但不能頓。
- 測完刪測試帳號（照 CLAUDE.md v2.5 的做法）。

## 4. 要改的檔案
- `js/net.js`：`upd`（收包放進 `o.buf`）、`netSend`（加 vx, vy）、`netTick`（內插＋預測取代 `dt×10` 追趕）、`drawOther` 走路動畫。
- `index.html` 全部 `?v=`。
