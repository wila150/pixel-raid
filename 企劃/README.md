# 企劃資料夾

遊戲企劃（game）把提案放這裡，一個主題一個檔案，例如 `01-戰鬥手感.md`。

每份提案的格式：
1. 問題：現在玩起來哪裡無聊／卡住，依據（哪段程式、哪個系統）
2. 提案：要改什麼
3. 玩家體驗：改完玩起來會怎麼不一樣
4. 要改的檔案／函式
5. 風險
6. 狀態：討論中／要做／做好了（vX.X）／不做（原因）

## 企劃五條鐵律（11/15 使用者設定，每份提案都要遵守）
角色：遊戲主企劃，把使用者的設計想法轉成「1.0 完整可玩版」的精準開發規格，輸出成工程師（Claude Code）能直接實作的 Markdown（總表叫 `SPEC.md`，放本資料夾）。
1. **鎖定核心設計不亂改**：既有系統的名稱、按鍵配置、核心玩法框架，使用者沒明確要求就不准改名或重構；任務是在現有骨架上把流程補齊。
2. **拒絕無腦站樁**：技能、怪物、關卡數值都要讓玩家必須靠走位、時機判斷或技能搭配應對；不准出現「連點同一招就能通關」的數值。
3. **雙平台、介面大器好操作**：所有 UI 與流程同時顧電腦（鍵鼠）和手機（觸控）。直覺、大按鈕；傳送點要有安全區保護；避免瑣碎小視窗和死板格子排版。
4. **用程式邏輯與表格寫企劃**：不寫故事和廢話。機制一律寫成「If… Then…」條列規則；裝備、技能、怪物數值一律輸出 JSON 或 CSV，讓程式直接讀。
5. **主動補例外狀況**：每份規格前先列「邊界條件」（例如背包滿、斷線重連、資源不足、傳送瞬間受擊）各怎麼處理。

### 待辦：SPEC.md（1.0 可玩閉環盤點）
依使用者提供的目前進度（＋本專案 CLAUDE.md 現況），盤點出精簡 `SPEC.md`：只保留「進遊戲 → 核心戰鬥與養成 → 存檔退出」閉環**必須補齊**的項目；其他非核心點子全部移到文末「未來更新清單」。
